# 遠征台帳の導入と保護

- 通常セーブと別のブラウザ内キーに、アカウント別・受取ID別に保存。残高はIDから再計算する。
- ゲストの台帳はログイン中の台帳へ自動移行しない。ブラウザデータ削除で端末のみの台帳は消失する。従来のJSONバックアップには含まれない。
- クラウド同期は `supabase/migrations/20261124_expedition_receipts.sql` のレビュー・適用後に専用ボタンを使用。既存のquest_savesは更新しない。現時点で本番DBには未適用。
- RLSで自分の行のみSELECT/INSERT可能。UPDATE/DELETEは許可しない。主キー(user_id, receipt_id)による重複排除。
- 現行アプリは自己申告ゲームで、報酬条件をサーバーで検証する仕組みではない。現金や交換可能な価値を付与しない。
- 導入前は別のテストプロジェクトで2アカウントのRLS、重複INSERT、ネット切断、PC/スマホ同時同期を検証する。ブラウザ側のテストはモックであり実DB確認の代替ではない。
- Phase 5のショップは複数端末での二重消費を防ぐ設計が別途必要。現時点の残高は獲得累計で、消費は未実装。
